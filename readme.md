# Retail Analytics: RFM Segmentation & Revenue Forecasting

## Project Overview

This project analyzes the **UCI Online Retail** transactional dataset to understand sales performance, segment customers using **RFM analysis**, and evaluate simple models for **weekly revenue forecasting**.

The project combines:

- **PostgreSQL** for data cleaning and SQL-based aggregation
- **Python / pandas** for analysis and customer segmentation
- **Matplotlib** for visualization
- **Statsmodels** for exponential smoothing forecasting
- **Jupyter Notebook** for the end-to-end analysis

## Business Objectives

1. Analyze revenue trends over time.
2. Identify customer groups based on purchasing behavior.
3. Evaluate simple approaches for short-term weekly revenue forecasting.

## Dataset

The project uses the **UCI Online Retail** dataset containing transactional records from a UK-based online retailer.

The dataset is kept in data folder as:

```text
data/Online_Retail_Dataset.csv
```

## Data Preparation

The raw transaction data is cleaned in PostgreSQL before analysis.

The cleaning process includes:

- Removing records with missing `CustomerID`
- Removing records with `Quantity <= 0`
- Converting the invoice date into a timestamp
- Calculating transaction-level revenue:

```text
TotalPrice = Quantity × UnitPrice
```

The cleaned data is then queried from PostgreSQL into Python.

Records with non-positive quantities may represent returns, cancellations, or other non-positive quantity transactions. They are excluded because this project focuses on positive sales transactions.

## Sales Analysis

### Monthly Revenue

Monthly revenue is calculated using SQL aggregation:

```text
Revenue = SUM(TotalPrice)
```

The analysis examines revenue changes throughout the available period.

The dataset ends partway through December, so the December decline is interpreted cautiously because it does not represent a complete month.

### Top Products

The top 10 products are identified using total quantity sold.

This measures **unit volume**, not product revenue.

## RFM Customer Segmentation

RFM analysis is used to understand customer purchasing behavior.

### Recency

How recently a customer made a purchase. More recent customers receive higher Recency scores.

### Frequency

The number of distinct invoices associated with a customer. More frequent customers receive higher Frequency scores.

### Monetary

The total revenue generated by a customer. Higher-spending customers receive higher Monetary scores.

Each RFM dimension receives a score from **1 to 4**.

Because many customers have identical frequency values, frequency values are ranked before quartile scoring so that four scoring groups can be created.

### Customer Segments

| Segment | Definition |
|---|---|
| High Value | R score ≥ 3, F score ≥ 3, and M score ≥ 3 |
| Loyal | R score ≥ 3 and F score ≥ 2, excluding customers already classified as High Value |
| Low Value | All remaining customers |

High Value is checked first in the segmentation logic, so customers meeting the High Value criteria are not also classified as Loyal.

## Revenue Forecasting

Weekly revenue is used for forecasting because the monthly dataset contains relatively few observations for robust model evaluation.

The forecasting workflow uses chronological data splitting:

```text
Training → Validation → Final Test
```

The current setup uses:

- 36 training weeks
- 8 validation weeks
- 8 final test weeks

Three forecasting approaches are evaluated:

### 1. Naive Forecast

Uses the most recent available value as the next forecast and recursively continues for future periods.

### 2. 4-Week Moving Average

Uses the average of the previous four observations. Multi-step forecasts are generated recursively so future actual values are not used.

### 3. Holt Exponential Smoothing

Uses Holt's additive trend exponential smoothing model without seasonality.

### Model Evaluation

Models are first evaluated on the validation period. The model with the lowest validation **MAPE (Mean Absolute Percentage Error)** is selected as the validation-selected model.

The final test period remains unseen during model development. All candidate models are evaluated on the final test period to report performance on unseen data.

## Key Findings

- High Value customers represent approximately **30.4% of customers** but contribute approximately **73.0% of revenue**, showing substantial revenue concentration.
- The dataset's December period is incomplete, so the December revenue decline should not be interpreted as a full-month trend.
- Weekly forecasting provides more observations for model evaluation than monthly forecasting.
- Naive, 4-week moving average, and Holt exponential smoothing models are compared using chronological validation and final testing.

Windows:


### 2. Install dependencies


Create a PostgreSQL database for the project.

Create a `.env` file in the project root:

```env

POSTGRES_PASSWORD=your_password
```

Use:

Open:


Run the notebook from top to bottom.

6. Generates visualizations

## Limitations

- The dataset ends partway through December, so December does not represent a complete month.
- The analysis excludes non-positive quantity transactions, so returns and cancellations are not modeled separately.
- RFM segmentation uses project-defined quartile scoring and business rules rather than a supervised learning model.
- Frequency values contain many ties; ranking is used before quartile scoring to create four scoring groups.
- The forecasting models are intentionally simple baseline models rather than a production forecasting system.
- The available time series is relatively short, limiting the complexity of models that can be reliably evaluated.
- Forecast accuracy metrics depend on the selected historical train, validation, and test periods.
